## Описание проекта

RBAC System — это консольное приложение на Java, реализующее гибкую систему управления доступом на основе ролей (Role-Based Access Control). Система позволяет:

- управлять пользователями, ролями и правами (permissions);
- назначать пользователям роли (постоянные или временные);
- проверять наличие прав у пользователя;
- вести аудит действий с асинхронной записью в лог;
- генерировать отчёты (пользователи, роли, матрица прав);
- выполнять параллельные и асинхронные операции;
- проводить нагрузочное тестирование корректности потоковой работы.

Приложение разработано с учётом требований потокобезопасности, расширяемости и удобства использования через командную строку.

## Основные возможности

### Пользователи (`User`)
- Создание, просмотр, обновление, удаление пользователей.
- Валидация: username (3–20 символов, буквы/цифры/`_`), email, полное имя (имя и фамилия).
- Поиск по username, email, домену, части имени.

### Роли (`Role`)
- Создание, удаление, изменение названия и описания.
- Добавление / удаление прав (permission).
- Поиск ролей по имени, наличию права, минимальному количеству прав.
- Невозможно удалить роль, если она назначена хотя бы одному пользователю.

### Назначения ролей (`Assignment`)
- Постоянное назначение (`PermanentAssignment`).
- Временное назначение (`TemporaryAssignment`) с датой истечения.
- Автоматическая проверка активности назначений (в том числе по расписанию).
- Отзыв назначений, продление временных назначений.
- Фильтрация: по пользователю, роли, типу, активности, дате назначения/истечения.

### Права (`Permission`)
- Право определяется тройкой: имя (READ/WRITE/DELETE/EXECUTE и др.), ресурс (users, reports, settings...), описание.
- Нормализация: имя -> верхний регистр, ресурс -> нижний регистр.
- Проверка наличия права у пользователя через роли.

### Командная строка (`CLI`)
- Регистрация команд с помощью `CommandParser`.
- Интерактивный ввод с подсказками, валидацией, выбором из списка.
- Доступные команды:
  - `user-list`, `user-create`, `user-view`, `user-update`, `user-delete`, `user-search`
  - `role-list`, `role-create`, `role-view`, `role-update`, `role-delete`, `role-add-permission`, `role-remove-permission`, `role-search`
  - `assign-role`, `revoke-role`, `assignment-list`, `assignment-list-user`, `assignment-list-role`, `assignment-active`, `assignment-expired`, `assignment-extend`, `assignment-search`
  - `permissions-user`, `permissions-check`
  - `stats`, `audit-log`, `audit-log-file`, `report-users`, `report-roles`, `report-matrix`, `report-users-async`, `save-async`
  - `help`, `clear`, `exit`

### Аудит (`AuditLog`)
- Асинхронное логирование через `BlockingQueue`.
- Запись времени, действия, исполнителя, цели, деталей.
- Просмотр логов в консоли или сохранение в файл.
- Потокобезопасное завершение при выключении системы.

### Отчёты (`ReportGenerator`)
- По пользователям: список активных ролей.
- По ролям: количество активных пользователей.
- Матрица прав: для каждого пользователя и ресурса – первая буква разрешений (R,W,D,E...).
- Параллельные версии генерации отчётов (через `parallelStream`).

### Фоновые задачи
- Периодическая проверка истёкших временных назначений (каждые 30 секунд).
- Периодическое логирование статистики (каждые 60 секунд).
- Асинхронное сохранение данных в JSON и генерация отчётов с использованием `ExecutorService`.

### Нагрузочное тестирование (`LoadTest`)
- 10 потоков, 50 операций на поток.
- Операции: создание/обновление пользователей, создание ролей, назначение ролей, поиск, получение прав.
- Проверка отсутствия дубликатов и «осиротевших» назначений.
- Подтверждение потокобезопасности системы.


## Архитектура проекта

Проект организован по принципу разделения ответственности:

- **`core`** – основные интерфейсы (`Repository`), классы `RBACSystem` (главный контроллер), `Permission`.
- **`user`** – `User` (record), `UserManager` (хранилище + индексы), фильтры, сортировки.
- **`role`** – `Role`, `RoleManager`, фильтры, сортировки.
- **`assignment`** – `RoleAssignment` (интерфейс), `AbstractRoleAssignment`, `PermanentAssignment`, `TemporaryAssignment`, `AssignmentManager`, фильтры, сортировки.
- **`command`** – `CommandParser`, регистрация команд, реализация всех команд в пакете `registry`.
- **`util`** – `AuditLog`, `DateUtils`, `FormatUtils`, `ValidationUtils`, `ConsoleUtils`, `ReportGenerator`.
- **`test`** – юнит-тесты (`UserTest`, `RoleTest`, `PermissionTest`, `AuditLogTest`, `DateUtilsTest`, `ValidationUtilsTest`, `TestManagers`), а также `LoadTest`.

### Потокобезопасность
- Внутренние хранилища менеджеров используют `ConcurrentHashMap`.
- Критические секции защищены `ReentrantReadWriteLock` (для операций, требующих атомарного чтения-записи нескольких мап).
- `AuditLog` использует `BlockingQueue` и отдельный поток-потребитель.
- Параллельные операции опираются на `parallelStream` (для отчётов) и `ExecutorService` (для асинхронных задач).

### Сериализация
- Возможность сохранять состояние системы в JSON (через Jackson).
- Структура: `RBACSystemData` (списки пользователей, ролей, назначений).


## Технологии и инструменты

- **Java 21** – основной язык.
- **Gradle** – система сборки.
- **JUnit 5** – тестирование (включая параметризованные тесты и `@Nested`).

### Требования
- JDK 21 (рекомендуется Temurin или OpenJDK)

## Тестирование

### Юнит-тесты
- Покрыты основные классы: `User`, `Role`, `Permission`, `ValidationUtils`, `DateUtils`, `AuditLog`.
- Интеграционные тесты менеджеров (`TestManagers`) проверяют сценарии с участием пользователей, ролей и назначений.

### Нагрузочное тестирование
Класс `LoadTest` запускает многопоточную нагрузку и проверяет:
- отсутствие дублирующихся username / role name;
- отсутствие «осиротевших» назначений (ссылающихся на несуществующих пользователей или роли);
- корректность всех операций при параллельном выполнении.

Результаты тестирования подтверждают потокобезопасность системы.
